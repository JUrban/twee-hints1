# What chain hints cost per abstract second (19 Nov)

Started 19 Nov 2026, 05:11 UTC. Scratch runs in the session scratchpad; commands below.

## Why

* Production's deep levels (80 s chain, its 160 s resume, the 80 s variants) carry the chain hints of 10 siblings:
  3,000 to 10,000 hints a run. The last cost-centre profile (REPORT 2au, 17 Nov) was on pool hints, a few
  thousand at most. It found that hinted runs cost more mainly because hinted rules overlap more, so they make more
  pairs, not because of the hints' bookkeeping.
* exp24 showed that far goals do not pay at 80 s (0 of 32 so far). So production's progress rests on near goals'
  deep runs, and any saving per run there turns into more runs per CPU hour at every deep level.

## First measurement (05:11)

exp11's first wall command (KK_Kcom_to_aK1 276, 7,668 chain hints), twee-pg61 with production's TWEE_PG_ARGS, at
20 abstract s, `+RTS -s`:

| run | CPU s | considered pairs | rules | GC share |
|---|---:|---:|---:|---:|
| with the chain hints | 36.1 | 40,002 | 8,366 | 6% |
| without hints | 19.3 | 40,000 | 9,450 | 7% |

* The same abstract budget costs 1.87x the CPU with the hints. The searches differ (the hinted one makes fewer rules),
  so this is not yet the bookkeeping's share.
* GC is small in both, so the cost is in the mutator.

* **The hints' own bookkeeping is about 7%.** The rest of the doubled cost is the search: for the same 20,000
  considered pairs the hinted run made twice the critical pairs (414k against 211k), so twice the normalising, and
  twice the queue to renormalise.
* **Queue renormalisation is 27% of the hinted run.** Under `--abstract-time` it is free in abstract time, so its
  5% budget never binds (twee-e27's `--queue-cost K` charges it; the default 0 is production's).

## Is renormalising the queue doing anything? (05:21)

The same 20 s hinted run with `--queue-cost`:

| K | CPU s | output |
|---|---:|---|
| 0 (production) | 36.1 | |
| 0.008 (its real cost; the 5% budget binds) | **30.2** | byte-identical |
| 0.002 | 37.0 | byte-identical |

* So at 20 s, renormalising the queue changed nothing in the search and cost 16% of the CPU. It drops pairs that
  have become trivial, but those are dropped when they come out of the queue anyway, and their scores stay as
  they were.
* What it can still change: memory (the queue keeps stale pairs), and runs where a pair's simplified form scores
  differently (hint matches after new rules).
* **exp25** (from 05:29, 2 workers, hints/exp/exp25_run.sh) checks this on 80 s runs. 6 walls (3 exp11 proved, 3
  it did not) in three arms: base (production), k008, and never (`--cp-renormalise-threshold 1000`). It compares
  outputs, CPU and peak RSS. If outputs stay identical, production gets the flag with no A/B needed.

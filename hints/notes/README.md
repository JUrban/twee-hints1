# Experiment notes

One file per experiment, written when it starts and finished when it ends (user, 17 Nov: "write a short
report about every experiment we do", beside the results in REPORT.md). REPORT.md says what we know. These
notes say exactly what was run, why, and how to judge it, so that each one can be rerun and questioned later.

Name: `YYYY-MM-DD-<topic>.md`. Sections:

* **Question:** what we want to know, and who asked (quote the user).
* **Setup:** binaries, flags, goal sets and how they were chosen, context, budget (abstract s), workers,
  scripts (in hints/exp), data and output paths, commit. Start and end times (check `date`).
* **Results:** the numbers as measured, with the noise level of this kind of comparison.
* **Reading:** what the numbers do and do not show. Controls, leaks, confounders, earlier claims this
  corrects.
* **Decision and next:** what changes (defaults, production) and what to try next. REPORT section.

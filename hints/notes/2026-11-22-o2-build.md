# twee built with -O2 (exp62)

Written 22 Nov 2026, 16:33 UTC.

## Why

* Prover9-new's branch josef01-cpu-next (501 commits past master, to 21 Aug) is about build flags for the Prover9
  binary: it accepts portable LTO and rejects portable -O3 after paired CPU audits. REPORT 2d had not looked at it.
* twee.cabal and twee-lib.cabal set no optimization level, and ~/.cabal/config leaves `optimization` at its
  default, so every twee-eNN binary so far was built at GHC -O1. The only GHC-side test so far was the allocation
  area (-A16m/-A64m, slower; notes/2026-11-14-long-run-speed.md). There is no LLVM on this machine (no opt/llc).
* All runs use `--abstract-time 2000`: the search, and so the proofs, do not depend on speed. A faster binary does
  the same runs in less CPU, which the yield-driven cascade turns into more runs per CPU hour.

## Build

`git worktree add /project/hintwork/tw61o2 7e0c271` (twee-e61, production's binary since 18 Nov 07:30), then
`nice -n 10 cabal build exe:twee -O2 -j2` there (16:33; log loops/TW61O2.build.log). The binary goes to
/project/bin/twee-e61o2 with a wrapper twee-pg61o2 like twee-pg61; no existing binary is replaced.

## Benchmark

abs/o2bench.sh (exp/o2bench.sh): exp61's command (sets/z8u300 in loops/Z8F.ctx, 5 abstract s, solve_new.sh's model
and lemma options, 1 worker) in two arms at once, loops/OB1 (twee-pg61) and loops/OB2 (twee-pg61o2), so both see the
same machine load.

## Measures

* Identical searches: the same THM/NO per goal and the same proofs (proofs/ of the proved goals compared).
* CPU: the sum over goals and the median per-goal ratio OB2/OB1, from results.tsv rows.
* Decision: adopt for new binaries (and production's next restart) if the outputs match and OB2 saves at least 5%
  of the CPU; a smaller saving is within the machine's run-to-run noise.
